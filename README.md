# MidnaUdon EventPhotoSorter

**Ver1.20 / Windows用・イベント写真振り分けアプリ**

参考写真から人物の外見を照合し、イベントで撮った写真を人物ごとのフォルダへ整理します。VRChatなどのイベント運営者向けです。

<img src="assets/app_icon.png" alt="ミドナうどん工房" width="180">

GitHub：https://github.com/MidnaAlfort/EventPhotoSorter

※本ツールは私が関わっている学園型イベントや、フレンドが関わっている学園型イベントでの写真選定を楽にする目的として制作したものを公開しています。
個別の導入支援や操作案内などのサポートは行っておりません、ご了承ください。

## まず使いたい方へ

EXE配布版をフォルダごと展開して、`MidnaUdon EventPhotoSorter.exe` を起動してください。Pythonのインストールは不要です。
一般向けの手順・APIキーの準備・利用上の注意は [利用者向け説明書](docs/Readme.txt) にまとめています。

1. `参考画像/イベント名/区分/人物名/` に各人物の単独写真を入れます。区分は参加者・スタッフなど任意です。
2. `作業フォルダ` に写真を入れます。**成功した写真は移動するため、初めはコピーした写真で試してください。**
3. フォルダとクラス（イベント名）を選択し、シンプル設定のモード・枚数を指定して開始します。
4. 最初は20枚程度で確認し、枚数を0にすると全件処理します。

```
参考画像/
└─ 交流会/
   ├─ 参加者/
   │  ├─ 人物A/参考.png
   │  └─ 人物B/参考.png
   └─ スタッフ/
      └─ 人物C/参考.png
```

## 判定モード

| モード | 選べる場所 | 動作 |
| --- | --- | --- |
| ローカルのみ | シンプル／詳細 | APIキー・API料金不要。複数人数には対応せず、人数・品質の分類はしません。複数人写真が個人フォルダに入る場合があります。 |
| 人物領域ハイブリッド | シンプル／詳細 | 人物領域を照合し、必要な判定にAPIを使用。複数人・大勢・ピンぼけ・品質が怪しい写真を各フォルダへ分類します。 |
| ハイブリッド | 詳細 | ローカルで候補を絞り、曖昧な写真をAPIで確認。ローカルで確定した写真では人数を確認しません。 |
| 固定参考API | 詳細 | 全員の参考画像をAPIへ渡して判定。一括1／2／4枚を選択できます。 |
| Jev特徴ハイブリッド（実験） | 詳細 | ローカルで確定できない写真をGPTで特徴抽出→Jevで照合。不確実・不一致・通信失敗時はGPT画像判定。OpenAIとTypeSafeの両キーが必要です。 |
| **DecisionAPI画像判定（おすすめ・起動時の初期値）** | **シンプル／詳細** | OpenAI Decisions APIで人数・中央の主役・人物照合を1回で判定。曖昧な写真だけGPT 6 Lunaで再判定し、それでも確定できなければ要確認へ。再判定は追加料金。OpenAIキーが必要です。利用できないアカウントでは人物領域ハイブリッドを選べます。 |

人物領域の既定値は大勢4人以上、ローカル優先・品質分類・曖昧な品質のAPI確認ON、API同時処理4件。中央の主役が十分大きく端の写り込みが小さい場合は個人へ分類します。自動判定には誤りがあるため、結果をご確認ください。

シンプル設定ではモード・枚数・APIキーを指定します。上り回線の設定はシンプル設定と詳細設定で共通です。

### 送信用JPEGと上り回線

- OpenAIの人物照合へ送る画像は、自動で参考写真を1枚20 KiB、対象写真を100 KiBに近づけます。すでに十分小さい送信用JPEGは追加で縮小せず、元写真は元の画質で振り分けます。
- 「OpenAIへの上り上限（Mbps）」で、複数の写真を並列処理している間も送信本文の合計速度を抑えられます。0.5 Mbpsは約62.5 kB/秒です。この上限はモデルのダウンロードや他のアプリの通信には適用されません。
- 同じ実写真100枚を各設定で1回判定したところ、小容量JPEGは送信本文が約208 MiBから57 MiBに減り、誤振り分けは12枚から14枚になりました。小容量・1 Mbpsでの所要時間は8分10秒でした。
- DecisionAPIは対象写真ごとに登録参考も送信します。「詳細設定」→「DecisionAPI設定」の「GPT照合用の参考を一時保存して上り通信量を減らす」は、GPTによる照合・再判定の参考送信に適用します。オンの場合は通常参考のJPEGを初回に1枚ずつ一時アップロードし、以後はファイルIDを使います。画像のトークン料金はファイルIDを使っても発生します。終了時に削除を要求し、中断時に備え作成から1時間の有効期限を設定します。Filesを使えない環境ではJPEG送信に戻ります。完了画面の詳細では、一時アップロードに使ったJPEG容量と待ち時間、終了時に削除を待った時間を確認できます。
- 振り分け用CLIでも小容量JPEGが既定です。従来画質との比較には `--upload-profile standard`、上り上限の指定には `--upload-limit-mbps 0.5`、GPT用の参考一時保存には `--reuse-uploaded-references` を使います。

### DecisionAPI画像判定（正式採用）

「シンプル設定」で **「DecisionAPI画像判定（おすすめ）」** を選び、OpenAI APIキーと枚数を入力して実行できます。起動時は毎回このモードを選択します。以前保存したモードがあっても初期選択はDecisionAPIです。しきい値や並列数など、その他の保存済み設定は復元します。シンプル設定はDecisionAPI・ローカルのみ・人物領域ハイブリッドの3項目です。固定参考APIは従来どおり詳細設定に残します。

DecisionAPIの利用可否はアカウントに依存します。利用できない場合は **「人物領域ハイブリッド」** へ切り替えてください。認証・利用権限・提供状況・残高不足・入力のエラー時はその実行を停止し、未処理の写真とエラーになった元写真は作業フォルダに残します。最初の実写真1枚で利用可否を確認し、応答後に残りを並列で送信します。標準の単独判定では、最初の応答を待つ間に次の写真をJPEGへ変換します。完了画面の詳細では、並列分のJPEG準備時間と送信・応答待ち時間の合計を確認できます。

標準の単独判定では、全員の参考画像と対象写真を同じ入力へ入れ、人数のChoice・主役のPredicate・人物のChoiceを1回で問い合わせます。参考は各人物の通常画像を最大3枚（`_local`除外）使用し、匿名IDで人物フォルダへ対応づけます。参考画像は実行開始時に一度だけ変換し、毎回同じ順序で対象写真の前に配置します。参考画像と対象写真はOpenAIへ送信されます。参考画像と完全一致する写真はAPIなしで分類します。

低確率・不明人物・回答拒否などの曖昧な判定は、全員の参考画像を使ってGPTで1回再判定します。初期モデルは **GPT 6 Luna (`gpt-6-luna`)** です。GPTでも曖昧な写真は「要確認」へ分けます。シンプル設定では再判定が有効です。詳細設定の「曖昧な写真をGPTで再判定」で変更できます。ピンぼけ分類は行いません。

接続切れ・タイムアウト・一時的なサーバーエラーや利用制限が出ると、以後のDecisionAPI送信を1件ずつに切り替え、待機を挟んで最大2回再試行します。判定要求が3件連続で失敗した場合や、APIが5秒を超える待機を指示した場合は、その実行を停止します。認証・権限・残高不足・証明書の検証失敗でも停止します。失敗・未処理の原本は作業フォルダに残ります。完了画面の詳細に通信エラーの分類が表示され、取得できた場合は問い合わせ用のAPIリクエストIDも表示されます。

OpenAIへのHTTPS接続では、同梱の信頼済み証明書に加え、Windowsが信頼するルート証明書を使います。環境変数で証明書を指定済みの場合は、その指定が優先されます。

「詳細設定」→「DecisionAPI設定」で採用基準を調整できます。シンプル設定では詳細の変更値を使わず、以下の既定値で実行します。しきい値を下げると誤分類も増え得ます。確信度・確率は実際の正答率ではありません。

| 設定 | 初期値 |
| --- | --- |
| 人数の最低選択確率 | 0.75 |
| 人物の最低確信度 | 0.75 |
| 人物の最低選択確率 | 0.75 |
| 人物の1位と2位の最低差 | 0.20 |
| 中央の主役の最低確率 | 0.85 |

主役が明確で人物照合が採用基準を満たした写真は、背景が大勢でも個人へ分類します。実際の人数は記録に残します。主役がいない確率が0.85以上なら複数人／大勢、0.15～0.85の間はGPT再判定の対象です（再判定OFFなら要確認）。詳細設定で主役をソロ扱いする機能をOFFにすると、複数人を個人へ分類しません。

参考＋対象の画像上限は128枚です。全人物を収められない場合や通常参考画像を持たない人物がいる場合は開始前に止め、人物を黙って候補から除外しません。作業写真の判定結果は永続キャッシュにしません。処理記録では確率・採用差・不採用理由・DecisionAPI専用の利用量を保存します。旧集計JSONの `decisions_experiment` キーは互換性のため維持し、料金範囲はDecisionAPI単独なら `openai_decisions`、GPT再判定を行った実行は `openai_decisions_and_responses` です。GPTへ回した写真数・分類できた数・要確認のままの数・失敗数も記録します。

DecisionAPIは `gpt-6-luna`・`POST /v1/decisions` を使用します。標準料金の短い入力では、100万トークンあたり通常入力$0.10、キャッシュ読込$0.01、キャッシュ書込$0.125で、出力は無料です。利用量を重複計上せず、1ドル150円で換算します。地域・長文加算は推定の対象外です。利用量未取得の呼出は料金不明と表示します。2026-11-18確認。 [OpenAI公式ガイド](https://developers.openai.com/api/docs/guides/decisions#pricing-and-availability) · [公式料金表](https://platform.openai.com/pricing/)

GPTを使う全モードの初期モデルも `gpt-6-luna` です。[GPT 6 Lunaの公式仕様](https://developers.openai.com/api/docs/models/gpt-6-luna)に合わせ、これまでの推論なし・低い出力量の設定を維持します。GPT Responses APIはStandardの短い入力に対して入力$0.10・キャッシュ読込$0.01・キャッシュ書込$0.125・出力$0.50 / 100万tokensで推定します。完了画面の料金はDecisionAPI分とGPT再判定分の合計です。追加のGPT呼び出しで時間と費用が増えます。長文・地域加算は含みません。

この更新の自動検証は合成画像・模擬応答で実施しています。試験方式の速度・料金・精度は、実写真を人が分類したうえで比較してください。初期値は現行の単独判定です。既存OpenAI SDKの認証・通信から汎用POSTを使うため、SDK更新は不要です。

CLIは `--mode decisions --dry-run --save-records`。詳細設定の固定参考APIは `--mode api` です。`--decisions-gpt-fallback` は初期ONです。`--no-decisions-gpt-fallback` でDecisionAPI単独にできます。「固定参考API／Decisionsを同じ写真で比較」で、写真を移動せず両方式の時間・推定料金・分類結果を比較できます。比較は両方式のAPI料金が発生します。

#### 高速化の試験と比較

「詳細設定」→「DecisionAPI設定」の「処理方式」で参考キャッシュ、JPEG品質82、2枚・4枚一括、GPU併用などを選べます。「現行・単独判定」が標準です。比較ボタンは写真を移動せず、複数方式のAPI料金が発生します。

「キャッシュ3方式の料金を比較」は、自動キャッシュ、参考部分だけのキャッシュ、キャッシュなしを、同じ写真と送信画質で比較します。完了画面の詳細と集計JSONの `decisions_cost` に通常入力・キャッシュ読込・書込の推定料金、GPT分、利用量未確認件数が出ます。CLIの `--decisions-cache-mode` には `implicit`、`references`、`off` のいずれかを指定できます。

- 参考キャッシュは固定の参考画像だけをOpenAI側で再利用します。送信データには各回の参考画像を添付します。圧縮と一括判定は送信量を減らす方式です。
- 一括判定は最初の実写真1枚で利用可否を確認してから開始します。回答の欠落や重複は該当写真を単独判定し、画像数の上限に収まらない束は単独判定します。認証・残高不足は停止し、通信失敗時は該当写真を作業フォルダに残します。
- 通信が乱れると同時通信を1件に制限します。再試行なしの成功が8件続くたび、2件、設定上限の順に戻します。通常の上限は4件です。完了画面の「詳細を表示」で実際の最大同時通信数、再送待機、API送信、GPT再判定を確認できます。
- GPU併用はCUDA版の試験設定です。鮮明な単独人物で、2種類の画像サイズで検出した人物領域と、切り抜き・全景で照合した候補が一致した場合だけAPIを省きます。CUDAを利用できない場合やローカル判定が難しい写真はDecisionAPIで判定します。

CLI比較では参考画像フォルダにクラスのフォルダを指定します。調整用の約60枚で各案を試し、採用候補を人手ラベル付きの別の140枚以上で比較します。ラベルJSONの形式は `{"label_source":"human","routes":{"撮影1.png":"生徒/登録名","撮影2.png":"複数人"}}` です。サブフォルダに同名画像がある場合は、作業フォルダからの相対パスで指定します。人物の所属名とフォルダ名は実際の参考画像に合わせます。

```powershell
python -m photo_sorter.benchmark --work "./調整用" --references "./参考画像/クラス名" --output "./比較結果/調整" --max-files 60 --strategies decisions_legacy decisions decisions_cached decisions_batch2 decisions_batch4 decisions_cached_batch2 decisions_cached_batch4 api4
python -m photo_sorter.benchmark --work "./最終評価用" --references "./参考画像/クラス名" --output "./比較結果/最終" --labels "./最終ラベル.json" --max-files 0 --strategies decisions_legacy decisions decisions_cached_batch2 api4 --repeat 3 --cache-pairs --warmup-work "./調整用" --accept-baseline decisions_legacy
python -m photo_sorter.benchmark --work "./速度評価100枚" --references "./参考画像/クラス名" --output "./比較結果/100枚" --max-files 100 --strategies decisions_legacy decisions decisions_cached_batch2 api4 --repeat 3 --cache-pairs --warmup-work "./調整用"
```

冷開始は事前判定を行わず、温開始は評価対象・参考画像と異なる写真で事前判定します。準備分の時間と料金は別に記録します。Decisionsは試行ごとに新しいキャッシュキーを使います。プロバイダー側のキャッシュ状態は応答の利用量で確認してください。準備用写真は固定参考4枚一括の比較時には4枚以上必要です。

採用には誤振り分け・要確認・失敗・推定料金の増加がなく、新たな人物取り違えもないことを確認します。参考画像と完全一致する写真は精度集計から除きます。100枚の所要時間の中央値が2分以内、または基準方式より20%以上の短縮が目標です。100枚の計時と人手ラベルでの品質評価を合わせて判断します。

固定参考APIは `api1 api2 api4`、CPU／GPU上のローカル処理は `local4 local8` で比較できます。GPU併用を比較するにはCUDA対応のPython環境で `decisions_gpu` または `decisions_gpu_cached_batch2` を追加します。結果の `decisions_run_details` で利用環境、`local_identity_images` と `reference_exact_images` でローカル判定と完全一致の枚数を確認できます。

`jev_images` はCLI比較専用の直接画像入力です。写真と参考画像をTypeSafeへ送信できる場合に `--strategies decisions_only jev_images --allow-jev-images` を使います。`JEV_API_Key` が必要です。TypeSafeの画像入力は試作向けで、現在の入力トークン単価は100万あたり$0.042です。 [TypeSafeの画像仕様](https://docs.typesafe.ai/images.md) · [TypeSafe公式料金](https://help.typesafe.ai/articles/5187202169-how-much-does-jev-cost)

#### GPUで主役と集合を先に判定する（比較専用）

GPU対応環境で既存の参考画像を使い、主役の全身・髪・上半身・衣装の特徴や集合写真の構図を照合します。GPUで確定した写真はAPI呼び出しが0回です。保留した写真は全員の通常参考画像と一緒にOpenAIへ送るため、OpenAI APIキーと利用料金が必要です。

1. 新方式を含むGPU版、または `setup_gpu.ps1` で準備した環境で `.\.venv_gpu\Scripts\python.exe app.py` を起動します。
2. 「詳細設定」で「DecisionAPI画像判定（おすすめ）」を選び、「DecisionAPI設定」の「処理方式」を「GPU主役判定＋Decisions（比較用）」または「GPU主役判定＋直接GPT（比較用）」にします。前者は保留写真をDecisionAPIで判定し、後者は保留写真を1枚ずつGPTへ直接送ります。
3. 作業フォルダ・参考クラス・枚数を選んで開始します。どちらも写真を移動せず、完了画面の詳細にGPUでAPIを省けた枚数が表示されます。CUDAが利用できない場合や途中でGPU処理に失敗した場合は、通常のDecisionAPI判定に切り替わります。通常起動時の初期値は「現行・単独判定」です。

CLIで同じ写真を3方式で比較する例です。結果は指定した出力先の `comparison.json` に保存されます。

```powershell
.\.venv_gpu\Scripts\python.exe -m photo_sorter.benchmark --work "./作業フォルダ" --references "./参考画像/クラス名" --output "./比較結果/GPU主役" --strategies decisions avatar_gpu_decisions avatar_gpu_gpt --max-files 20
```

1方式だけ試すときは `python -m photo_sorter.cli --mode decisions --avatar-gpu --work "./作業フォルダ" --references "./参考画像/クラス名" --output "./比較結果/単独" --max-files 20 --save-records` をGPU環境で実行します。GPTへ直接送る比較には `--avatar-direct-gpt` を追加します。

構図を追加確認するQwen3-VL-4B-Instructは研究用のCLIオプションです。手元に配置したモデルフォルダを `--avatar-scene-model "./models/Qwen3-VL-4B-Instruct"` で指定し、比較方式に `avatar_qwen_decisions` または `avatar_qwen_gpt` を追加します。アプリはQwenの重みを自動取得しません。

### Jev特徴ハイブリッド（実験）の試し方

設定画面に対応した実験版EXEは、プロジェクト直下の `MUEventPhotoSorter_Jev実験_設定対応.exe` です。通常の配布用EXE・以前の実験版とは別ファイルで、このEXEの横にある `.env` を読みます。

Jev特徴ハイブリッドでは、GPTが画像から英語の特徴カードを作り、Jevがカードを照合します。**対象写真の特徴抽出にもOpenAI APIを使用する実験であり、高速化・精度向上は未検証です。** ローカル画像モデルによる文章化は未実装です。

1. 「詳細設定」→「判定設定」のOpenAI APIキー欄と、「Jev実験設定」のJev APIキー欄にそれぞれ入力します。「APIキーを保存」ボタン、または実行・比較時に `.env` の `OPENAI_API_KEY` と `JEV_API_Key` へ保存します。既存の `.env` からも読み込めます。入力は伏字で、空欄にしても保存済みキーは削除しません。
2. 「詳細設定」→「判定設定」で「Jev特徴ハイブリッド（実験）」を選択します。
3. 最初は「一括判定・人物領域・比較」の **「従来ハイブリッド／Jev実験を比較」** を使用してください。写真を移動せず、両方式を同じ写真で実行し、出力先の `比較結果` に記録します。両サービスのAPI料金が発生します。
4. 単独で試す場合は「判定だけ試す」をONにして開始します。CSV・集計JSONも必要なら「処理記録を保存」をONにします。判定だけ試すをOFFにすると、他のモードと同様に成功した写真を移動します。

起動後の参考準備では、各人物の通常参考画像を最大3枚ずつ文章化します（`_local` の追加写真は除外）。明確な単独人物として特徴を取得できたカードだけを `アプリデータ/model_cache/jev_reference_features.sqlite3` に保存し、画像内容・GPTモデル・抽出仕様が変わらなければ再利用します。作業写真の特徴とJevの判定は保存キャッシュにしません。カードキャッシュは処理記録OFFでも保存され、不要ならアプリ停止中にこのファイルだけを削除できます。

参考特徴を作れない人物がいる場合や登録人数が254人を超える場合、人物を候補から黙って除外せず、Jev照合を見送ってGPT画像判定を使います。参考準備のキャンセルにも対応します。

「詳細設定」→「Jev実験設定」で、作業写真の採用基準を変更できます。

| 項目 | 初期値 | 範囲 |
| --- | --- | --- |
| 特徴抽出の最低確信度 | 0.95 | 0～1 |
| 最低特徴項目数（体・髪・耳・服・装飾品の5項目中） | 3 | 1～5の整数 |
| Jevの最低確信度 | 0.95 | 0～1 |
| Jevの最低選択確率 | 0.95 | 0～1 |
| Jevの1位と2位の最低差 | 0.90 | 0～1 |

すべての条件を満たした場合に採用します。初期値は以前の実験版と同じです。「しきい値を初期値へ戻す」で戻せます。小さくすると対象・採用が増える可能性がありますが、誤分類も増え得ます。確信度は正答率ではありません。

値は実行・比較時に `アプリデータ/settings.json` へ保存し、次回起動時に読み込みます。APIキーはこの設定ファイルに保存しません。比較ボタンでも同じしきい値を使用し、集計JSONの設定欄に記録します。シンプル設定やJevを使わない通常実行では、このタブの数値は判定に影響しません。CLIの通常起動は引き続き初期値を使用します。

参考特徴の作成・キャッシュの基準は従来の0.95・3項目のまま固定です。作業写真についても、単独・鮮明・不確実でないこと、固有特徴があること、ローカル1位候補との一致は必須です。不明・未登録・複数人・特徴不足は元画像でGPTへ再確認します。認証・レート制限エラー後は、その実行中の新たなJev照合を停止します。

既存ハイブリッドと同じく、ローカルだけで確定した写真では人数を確認しません。**この実験モードは人物領域モードのピンぼけ分類を行いません。** 似た外見、鏡・スクリーン、衣装変更、写り込みを含む写真も比較対象に含めてください。

画像はOpenAIへ送信し、Jevには匿名候補IDと外見の特徴テキストをTypeSafe公式APIへ送信します。人物フォルダ名・ファイルパス・画像データをJevリクエストに組み込みません。`.env` のキーは処理記録へ保存しません。

記録には `feature_calls/feature_seconds`、`jev_calls/jev_seconds`、`jev_input_tokens/jev_output_tokens`、確信度・確率・GPTへ戻した理由が含まれます。`decision_source=jev` はJev確定、`jev_fallback` はGPTへのフォールバックです。参考準備の利用量は先頭の写真の行へ一度だけ加算し、準備時間は集計JSONにも分けて記録します。並列処理の各API秒数の合計は、実際の経過時間とは異なります。

**画面・比較結果の推定料金はOpenAI分のみで、Jev料金は含みません。** Jevのトークン数を別に記録します。初回の参考作成を含む時間と、参考キャッシュがある2回目以降の時間を分け、正解を人が確認した写真で誤分類率・GPTへ戻る割合・総経過時間を比較してください。比較順序やモデルの初回読込も時間に影響します。正解ラベルなしの方式比較だけでは精度は測れません。

```powershell
.\.venv\Scripts\python.exe -m photo_sorter.cli --mode jev --references 参考画像/交流会 --output 振り分け後/交流会 --max-files 20 --dry-run --save-records
.\.venv\Scripts\python.exe -m photo_sorter.benchmark --work 作業フォルダ --references 参考画像/交流会 --output 比較結果 --strategies hybrid jev --max-files 20
```

特徴照合は比較条件を固定するため `jev-1.13.0` を使用します。 [TypeSafeのChoice API](https://docs.typesafe.ai/primitives/choice)

## APIキーと画像の送信

人物領域ハイブリッドには、ChatGPTのAPIキーが必要です（各自で発行してください）。正確にはOpenAIの開発者向けAPIキーで、通常のChatGPTの画面に写真を送る方式ではありません。

[OpenAIのAPIキー作成画面](https://platform.openai.com/api-keys)でキーを作成し、アプリへ入力して実行すると、EXEと同じ場所の `.env` に保存して次回から読み込みます。公式の作成手順は [OpenAI Developer quickstart](https://developers.openai.com/api/docs/quickstart) を参照してください。

APIを使うモードでは、判定対象の画像・切り抜き・参考画像と、参考画像フォルダの区分名／人物名に由来する識別子が必要に応じてOpenAIへ送信され、利用料金が発生します。ローカルのみでは判定のための画像をAPIへ送信しません。モデルがない場合の初回取得は別途通信します。送信について必要な権利・許諾を確認し、人物名フォルダに送信に適さない本名や秘密の情報を入れないでください。

APIデータは通常、明示的な共有同意がなければモデル学習に使われませんが、不正利用監視等の保持条件は別です。`store=False`やアプリの記録OFFはゼロ保持を意味しません。[OpenAI公式のデータ管理](https://developers.openai.com/api/docs/guides/your-data)

`.env` は平文です。APIキーや実写真をGitHubへアップロードしないでください。起動時は `.env` の `OPENAI_API_KEY` を優先します。未設定・空欄の場合はOSの環境変数を使用し、そのキーを `.env` へ保存しません。キーの保存に失敗した場合は処理を開始しません。

## 出力・詳細設定

成功した写真は `振り分け後/イベント名/区分/人物名/` などへ移動します。人物を確定できない写真・複数人・大勢・人物なし・ピンぼけ・品質要確認は `複数人or未分類/` 内の各フォルダに入ります。処理エラーの元画像は作業フォルダに残します。

詳細設定には、APIモデル・候補数・しきい値・並列数・主役扱い・人数先行判定・参考領域再利用・連写共有・品質判定・手動の人物領域指定・方式比較を用意しています。下の項目は右側のスクロールバーで表示できます。

「判定だけ試す」は写真を移動しませんが、API料金は発生します。「処理記録を保存」は初期OFFです。ONにするとCSV・集計JSON・再開用JSON/SQLiteを保存し、OFFでも画面に進捗・時間・推定料金を表示します。方式比較は記録設定と独立して結果を保存します。モデル／参考領域キャッシュと画面設定は処理記録とは別です。

## 完了画面

全モードで、処理枚数・振り分け済み／要確認／失敗の枚数・所要時間・推定料金を同じ配置で表示します。写真1枚は結果のいずれか1つに数えます。「判定だけ試す」では移動済みと表示しません。通信失敗を要確認の写真へ混ぜず、失敗した原本を再実行できます。

API呼び出し数・再試行回数・トークン数・GPT再判定で分類できた枚数・保存先ごとの内訳・要確認の主な理由は「詳細を表示」で確認できます。同じ写真の複数の不採用条件は、主な理由1つとして数えます。料金は一度だけ表示し、利用量未取得の呼び出しがある場合は取得分のみの推定と明示します。全利用量が不明なら0円とは表示しません。Jevモードの推定料金はOpenAI分のみです。
