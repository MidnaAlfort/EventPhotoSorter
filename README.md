# MidnaUdon EventPhotoSorter

**Ver1.10 / Windows用・イベント写真振り分けアプリ**

参考写真から人物の外見を照合し、イベントで撮った写真を人物ごとのフォルダへ整理します。VRChatなどのイベント運営者向けです。

<img src="assets/app_icon.png" alt="ミドナうどん工房" width="180">

GitHub：https://github.com/MidnaAlfort/EventPhotoSorter

※本ツールは私が関わっている学園型イベントや、フレンドが関わっている学園型イベントでの写真選定を楽にする目的として制作したものを公開しています。
個別の導入支援や操作案内などのサポートは行っておりません、ご了承ください。

## まず使いたい方へ

EXE配布版をフォルダごと展開して、`MidnaUdon EventPhotoSorter.exe` を起動してください。Pythonのインストールは不要です。
一般向けの手順・APIキーの準備・利用上の注意は [利用者向け説明書](docs/Readme.txt) にまとめています。

1. `参考画像/イベント名/区分/人物名/` に各人物の単独写真を入れます。区分は参加者・スタッフなど任意です。
2. `作業フォルダ` に写真を入れます。**成功した写真は移動するため、初めはコピーした写真で試してください。**
3. フォルダとクラス（イベント名）を選択し、シンプル設定のモード・枚数を指定して開始します。
4. 最初は20枚程度で確認し、枚数を0にすると全件処理します。

```
参考画像/
└─ 交流会/
   ├─ 参加者/
   │  ├─ 人物A/参考.png
   │  └─ 人物B/参考.png
   └─ スタッフ/
      └─ 人物C/参考.png
```

## 判定モード

| モード | 選べる場所 | 動作 |
| --- | --- | --- |
| ローカルのみ | シンプル／詳細 | APIキー・API料金不要。複数人数には対応せず、人数・品質の分類はしません。複数人写真が個人フォルダに入る場合があります。 |
| 人物領域ハイブリッド | シンプル／詳細 | 人物領域を照合し、必要な判定にAPIを使用。複数人・大勢・ピンぼけ・品質が怪しい写真を各フォルダへ分類します。 |
| ハイブリッド | 詳細 | ローカルで候補を絞り、曖昧な写真をAPIで確認。ローカルで確定した写真では人数を確認しません。 |
| 固定参考API | 詳細 | 全員の参考画像をAPIへ渡して判定。一括1／2／4枚を選択できます。 |
| Jev特徴ハイブリッド（実験） | 詳細 | ローカルで確定できない写真をGPTで特徴抽出→Jevで照合。不確実・不一致・通信失敗時はGPT画像判定。OpenAIとTypeSafeの両キーが必要です。 |
| **DecisionAPI画像判定（おすすめ・起動時の初期値）** | **シンプル／詳細** | OpenAI Decisions APIで人数・中央の主役・人物照合を1回で判定。曖昧な写真だけGPT 6 Lunaで再判定し、それでも確定できなければ要確認へ。再判定は追加料金。OpenAIキーが必要です。利用できないアカウントでは人物領域ハイブリッドを選べます。 |

人物領域の既定値は大勢4人以上、ローカル優先・品質分類・曖昧な品質のAPI確認ON、API同時処理4件。中央の主役が十分大きく端の写り込みが小さい場合は個人へ分類します。自動判定には誤りがあるため、結果をご確認ください。

シンプル設定の入力欄はモード・枚数設定・APIキーのみです。詳細設定の変更値は使わず既定値で実行します。APIキーと枚数は共通です。

### DecisionAPI画像判定（正式採用）

「シンプル設定」で **「DecisionAPI画像判定（おすすめ）」** を選び、OpenAI APIキーと枚数を入力して実行できます。起動時は毎回このモードを選択します。以前保存したモードがあっても初期選択はDecisionAPIです。しきい値や並列数など、その他の保存済み設定は復元します。シンプル設定はDecisionAPI・ローカルのみ・人物領域ハイブリッドの3項目です。固定参考APIは従来どおり詳細設定に残します。

DecisionAPIの利用可否はアカウントに依存します。利用できない場合は **「人物領域ハイブリッド」** へ切り替えてください。認証・利用権限・提供状況・残高不足・入力のエラー時はその実行を停止し、未処理の写真とエラーになった元写真は作業フォルダに残します。最初の実写真1枚で利用可否を確認してから残りを並列処理するため、利用不可時の一斉送信を防ぎます。確認専用の追加API呼出はありません。

各写真について、全員の参考画像と対象写真を同じ入力へ入れ、人数のChoice・主役のPredicate・人物のChoiceを1回で問い合わせます。参考は各人物の通常画像を最大3枚（`_local`除外）使用し、匿名IDで人物フォルダへ対応づけます。参考画像は実行開始時に一度だけ変換し、毎回同じ順序で対象写真の前に配置します。特徴の文章化・ローカルモデルの候補一致・追加の人数APIは使いません。参考画像と対象写真はOpenAIへ送信されます。参考画像と完全一致する写真はAPIなしで分類します。

低確率・不明人物・回答拒否などの曖昧な判定は、全員の参考画像を使ってGPTで1回再判定します。初期モデルは **GPT 6 Luna (`gpt-6-luna`)** です。DecisionAPIで確定できた写真には追加のGPT呼び出しを行いません。GPTでも曖昧な写真だけ「要確認」へ分けます。接続切れ・タイムアウト・一時的なサーバーエラー・短時間の利用制限では、最大2回の通信再試行を行います。認証・権限・残高不足では再試行しません。長い待機を求められた場合は早期に再送せず、後から再実行できるよう失敗として残します。再試行後も通信が失敗する場合や不整合な応答は処理エラーとし、原本を作業フォルダに残します。利用権限等の継続処理ができないエラーは前述のとおり停止します。シンプル設定は再判定ONです。詳細設定の「曖昧な写真をGPTで再判定」でOFFにでき、設定は保存します。ピンぼけ分類は行いません。

「詳細設定」→「DecisionAPI設定」で採用基準を調整できます。シンプル設定では詳細の変更値を使わず、以下の既定値で実行します。しきい値を下げると誤分類も増え得ます。確信度・確率は実際の正答率ではありません。

| 設定 | 初期値 |
| --- | --- |
| 人数の最低選択確率 | 0.75 |
| 人物の最低確信度 | 0.75 |
| 人物の最低選択確率 | 0.75 |
| 人物の1位と2位の最低差 | 0.20 |
| 中央の主役の最低確率 | 0.85 |

主役が明確で人物照合が採用基準を満たした写真は、背景が大勢でも個人へ分類します。実際の人数は記録に残します。主役がいない確率が0.85以上なら複数人／大勢、0.15～0.85の間はGPT再判定の対象です（再判定OFFなら要確認）。詳細設定で主役をソロ扱いする機能をOFFにすると、複数人を個人へ分類しません。

参考＋対象の画像上限は128枚です。全人物を収められない場合や通常参考画像を持たない人物がいる場合は開始前に止め、人物を黙って候補から除外しません。作業写真の判定結果は永続キャッシュにしません。処理記録では確率・採用差・不採用理由・DecisionAPI専用の利用量を保存します。旧集計JSONの `decisions_experiment` キーは互換性のため維持し、料金範囲はDecisionAPI単独なら `openai_decisions`、GPT再判定を行った実行は `openai_decisions_and_responses` です。GPTへ回した写真数・分類できた数・要確認のままの数・失敗数も記録します。

2026-10-09に確認した[OpenAI公式ガイド](https://developers.openai.com/api/docs/guides/decisions)では `gpt-6-luna`・`POST /v1/decisions` を使用し、入力100万tokensあたり$0.10、キャッシュ読込・書込の追加料金・出力料金はありません。推定料金は入力からキャッシュ読込分を引いて算出します。1ドル150円換算、地域・長文加算は含みません。利用量未取得の呼出は料金不明と表示します。

GPTを使う全モードの初期モデルも `gpt-6-luna` です。[GPT 6 Lunaの公式仕様](https://developers.openai.com/api/docs/models/gpt-6-luna)に合わせ、これまでの推論なし・低い出力量の設定を維持します。GPT Responses APIはStandardの短い入力に対して入力$0.10・キャッシュ読込$0.01・キャッシュ書込$0.125・出力$0.50 / 100万tokensで推定します。完了画面の料金はDecisionAPI分とGPT再判定分の合計です。追加のGPT呼び出しで時間と費用が増えます。長文・地域加算は含みません。

正式採用はユーザーの実写真での評価に基づきます。この更新の自動検証は合成画像・模擬応答で実施し、実APIでの更新後の速度・料金・精度は再計測していません。画像サイズ・参考枚数・採用しきい値は従来のDecisionAPI実装を維持しています。既存OpenAI SDKの認証・通信から汎用POSTを使うため、SDK更新は不要です。

CLIは `--mode decisions --dry-run --save-records`。詳細設定の固定参考APIは `--mode api` です。`--decisions-gpt-fallback` は初期ONです。`--no-decisions-gpt-fallback` でDecisionAPI単独にできます。「固定参考API／Decisionsを同じ写真で比較」で、写真を移動せず両方式の時間・推定料金・分類結果を比較できます。比較は両方式のAPI料金が発生します。

### Jev特徴ハイブリッド（実験）の試し方

Jev実験は通常のアプリの詳細設定から利用できます。APIキーはアプリと同じ場所の `.env` に保存します。

Jevは画像を直接読めません。このモードではGPTが画像から英語の特徴カードを作り、Jevがカードを照合します。**対象写真の特徴抽出にもOpenAI APIを使用する実験であり、高速化・精度向上は未検証です。** ローカル画像モデルによる文章化は未実装です。

1. 「詳細設定」→「判定設定」のOpenAI APIキー欄と、「Jev実験設定」のJev APIキー欄にそれぞれ入力します。「APIキーを保存」ボタン、または実行・比較時に `.env` の `OPENAI_API_KEY` と `JEV_API_Key` へ保存します。既存の `.env` からも読み込めます。入力は伏字で、空欄にしても保存済みキーは削除しません。
2. 「詳細設定」→「判定設定」で「Jev特徴ハイブリッド（実験）」を選択します。
3. 最初は「一括判定・人物領域・比較」の **「従来ハイブリッド／Jev実験を比較」** を使用してください。写真を移動せず、両方式を同じ写真で実行し、出力先の `比較結果` に記録します。両サービスのAPI料金が発生します。
4. 単独で試す場合は「判定だけ試す」をONにして開始します。CSV・集計JSONも必要なら「処理記録を保存」をONにします。判定だけ試すをOFFにすると、他のモードと同様に成功した写真を移動します。

起動後の参考準備では、各人物の通常参考画像を最大3枚ずつ文章化します（`_local` の追加写真は除外）。明確な単独人物として特徴を取得できたカードだけを `アプリデータ/model_cache/jev_reference_features.sqlite3` に保存し、画像内容・GPTモデル・抽出仕様が変わらなければ再利用します。作業写真の特徴とJevの判定は保存キャッシュにしません。カードキャッシュは処理記録OFFでも保存され、不要ならアプリ停止中にこのファイルだけを削除できます。

参考特徴を作れない人物がいる場合や登録人数が254人を超える場合、人物を候補から黙って除外せず、Jev照合を見送ってGPT画像判定を使います。参考準備のキャンセルにも対応します。

「詳細設定」→「Jev実験設定」で、作業写真の採用基準を変更できます。

| 項目 | 初期値 | 範囲 |
| --- | --- | --- |
| 特徴抽出の最低確信度 | 0.95 | 0～1 |
| 最低特徴項目数（体・髪・耳・服・装飾品の5項目中） | 3 | 1～5の整数 |
| Jevの最低確信度 | 0.95 | 0～1 |
| Jevの最低選択確率 | 0.95 | 0～1 |
| Jevの1位と2位の最低差 | 0.90 | 0～1 |

すべての条件を満たした場合に採用します。初期値は以前の実験版と同じです。「しきい値を初期値へ戻す」で戻せます。小さくすると対象・採用が増える可能性がありますが、誤分類も増え得ます。確信度は正答率ではありません。

値は実行・比較時に `アプリデータ/settings.json` へ保存し、次回起動時に読み込みます。APIキーはこの設定ファイルに保存しません。比較ボタンでも同じしきい値を使用し、集計JSONの設定欄に記録します。シンプル設定やJevを使わない通常実行では、このタブの数値は判定に影響しません。CLIの通常起動は引き続き初期値を使用します。

参考特徴の作成・キャッシュの基準は従来の0.95・3項目のまま固定です。作業写真についても、単独・鮮明・不確実でないこと、固有特徴があること、ローカル1位候補との一致は必須です。不明・未登録・複数人・特徴不足は元画像でGPTへ再確認します。認証・レート制限エラー後は、その実行中の新たなJev照合を停止します。

既存ハイブリッドと同じく、ローカルだけで確定した写真では人数を確認しません。**この実験モードは人物領域モードのピンぼけ分類を行いません。** 似た外見、鏡・スクリーン、衣装変更、写り込みを含む写真も比較対象に含めてください。

画像はOpenAIへ送信し、Jevには匿名候補IDと外見の特徴テキストをTypeSafe公式APIへ送信します。人物フォルダ名・ファイルパス・画像データをJevリクエストに組み込みません。`.env` のキーは処理記録へ保存しません。

記録には `feature_calls/feature_seconds`、`jev_calls/jev_seconds`、`jev_input_tokens/jev_output_tokens`、確信度・確率・GPTへ戻した理由が含まれます。`decision_source=jev` はJev確定、`jev_fallback` はGPTへのフォールバックです。参考準備の利用量は先頭の写真の行へ一度だけ加算し、準備時間は集計JSONにも分けて記録します。並列処理の各API秒数の合計は、実際の経過時間とは異なります。

**画面・比較結果の推定料金はOpenAI分のみで、Jev料金は含みません。** Jevのトークン数を別に記録します。初回の参考作成を含む時間と、参考キャッシュがある2回目以降の時間を分け、正解を人が確認した写真で誤分類率・GPTへ戻る割合・総経過時間を比較してください。比較順序やモデルの初回読込も時間に影響します。正解ラベルなしの方式比較だけでは精度は測れません。

```powershell
.\.venv\Scripts\python.exe -m photo_sorter.cli --mode jev --references 参考画像/交流会 --output 振り分け後/交流会 --max-files 20 --dry-run --save-records
.\.venv\Scripts\python.exe -m photo_sorter.benchmark --work 作業フォルダ --references 参考画像/交流会 --output 比較結果 --strategies hybrid jev --max-files 20
```

公式仕様: [画像入力の制限](https://docs.typesafe.ai/concepts/state)、[Choice API](https://docs.typesafe.ai/primitives/choice)。Jevモデルは比較条件を固定するため `jev-1.13.0` を使用します。

## APIキーと画像の送信

人物領域ハイブリッドには、ChatGPTのAPIキーが必要です（各自で発行してください）。正確にはOpenAIの開発者向けAPIキーで、通常のChatGPTの画面に写真を送る方式ではありません。

[OpenAIのAPIキー作成画面](https://platform.openai.com/api-keys)でキーを作成し、アプリへ入力して実行すると、EXEと同じ場所の `.env` に保存して次回から読み込みます。公式の作成手順は [OpenAI Developer quickstart](https://developers.openai.com/api/docs/quickstart) を参照してください。

APIを使うモードでは、判定対象の画像・切り抜き・参考画像と、参考画像フォルダの区分名／人物名に由来する識別子が必要に応じてOpenAIへ送信され、利用料金が発生します。ローカルのみでは判定のための画像をAPIへ送信しません。モデルがない場合の初回取得は別途通信します。送信について必要な権利・許諾を確認し、人物名フォルダに送信に適さない本名や秘密の情報を入れないでください。

APIデータは通常、明示的な共有同意がなければモデル学習に使われませんが、不正利用監視等の保持条件は別です。`store=False`やアプリの記録OFFはゼロ保持を意味しません。[OpenAI公式のデータ管理](https://developers.openai.com/api/docs/guides/your-data)

`.env` は平文です。APIキーや実写真をGitHubへアップロードしないでください。OSに `OPENAI_API_KEY` を設定している場合は起動時にそちらを優先します。キーの保存に失敗した場合は処理を開始しません。

## 出力・詳細設定

成功した写真は `振り分け後/イベント名/区分/人物名/` などへ移動します。人物を確定できない写真・複数人・大勢・人物なし・ピンぼけ・品質要確認は `複数人or未分類/` 内の各フォルダに入ります。処理エラーの元画像は作業フォルダに残します。

詳細設定には、APIモデル・候補数・しきい値・並列数・主役扱い・人数先行判定・参考領域再利用・連写共有・品質判定・手動の人物領域指定・方式比較を用意しています。下の項目は右側のスクロールバーで表示できます。

「判定だけ試す」は写真を移動しませんが、API料金は発生します。「処理記録を保存」は初期OFFです。ONにするとCSV・集計JSON・再開用JSON/SQLiteを保存し、OFFでも画面に進捗・時間・推定料金を表示します。方式比較は記録設定と独立して結果を保存します。モデル／参考領域キャッシュと画面設定は処理記録とは別です。

## 完了画面

全モードで、処理枚数・振り分け済み／要確認／失敗の枚数・所要時間・推定料金を同じ配置で表示します。写真1枚は結果のいずれか1つに数えます。「判定だけ試す」では移動済みと表示しません。通信失敗を要確認の写真へ混ぜず、失敗した原本を再実行できます。

API呼び出し数・再試行回数・トークン数・GPT再判定で分類できた枚数・保存先ごとの内訳・要確認の主な理由は「詳細を表示」で確認できます。同じ写真の複数の不採用条件は、主な理由1つとして数えます。料金は一度だけ表示し、利用量未取得の呼び出しがある場合は取得分のみの推定と明示します。全利用量が不明なら0円とは表示しません。Jevモードの推定料金はOpenAI分のみです。

Windows 10 / 11、64bit Python 3.12での実行を想定しています。初回のモデル取得にインターネット接続が必要です。

```powershell
.\setup.bat
.\start.bat
```

手動の場合：

```powershell

.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe app.py
```

## EXEのビルド

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-build.txt
.\.venv\Scripts\python.exe tools/download_models.py
.\build_exe.ps1
```

ビルドにはVisual Studio 2022のVC++ x64再配布用CRTが必要です。通常は自動検出します。別のインストール先は `EVENTPHOTOSORTER_VC_REDIST` で `VC/Redist/MSVC/14.x/x64/Microsoft.VC143.CRT` を指定してください。DLL探索先をPython・公式CRT・Windowsに限定し、別アプリのDLLを検出した場合はビルドを停止します。DbgHelp・DbgCore・UCRT・API-setはWindows 10/11標準の部品を使います。

`配布用/MidnaUdon EventPhotoSorter/` は手元で使うフォルダとして更新し、既存の写真やキーを保持します。**この利用済みフォルダをそのまま公開しないでください。** 更新前EXEは `artifacts/exe_backups/` に保存します。

公開に使うのは、新規作成される `公開用/EventPhotoSorter-v1_10-Windows-日時.zip` です。許可したEXE・文書・ライセンス・固定リビジョンのモデルだけを収録し、キー・写真フォルダは空、利用履歴や特徴量キャッシュは除外します。ネイティブ部品の取得元とハッシュは `licenses/native_dependencies.json`、公開ファイル全体は `RELEASE_MANIFEST.json` に記録します。

配布版の初回起動時にMicrosoftランタイムの利用条件を確認します。これは同梱Microsoft部品に適用され、アプリ本体のMITライセンスは変わりません。

GPU版は `setup_gpu.ps1` で対応GPU・CUDA環境を準備し、`build_gpu_exe.ps1` でビルドします。GPU版EXEは親フォルダの写真・キー・モデルを共有します。GPU環境のライセンスも収集して配布してください。


`公開用/` に新しいソースフォルダとZIPを作ります。コード・テスト・ビルドスクリプト・ロゴ・docs内の説明書・ライセンスを明示的に選んでコピーします。`.git`、過去の履歴、`.env`、写真、モデルの重み、EXE、仮想環境、実験ログは含めません。ファイル別SHA-256は `SOURCE_MANIFEST.json` にあります。

## APIキーを記録へ残さないための処理

APIのエラー本文はそのまま記録せず、種類とHTTP状態を表示します。その他のメッセージでも、設定したOpenAI・Jevキー、Bearer認証値、既知のキーパターンは伏せます。画面ログ・進捗・CSV・JSON・再開用の記録にも同じ処理を適用します。キー自体はローカルの.envに保存する従来仕様です。公開用の.env.exampleは空欄で、実際の.envや利用済み記録は公開用ソースへコピーしません。
